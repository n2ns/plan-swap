# PlanSwap 사용 설명서

[English](user-guide.md) · [简体中文](user-guide.zh-cn.md) · [繁體中文](user-guide.zh-tw.md) · [Español](user-guide.es.md) · [日本語](user-guide.ja.md) · **한국어**

PlanSwap을 사용하면 여러 Claude Code 계정과 Codex 계정에 로그인한 상태를 유지하면서 편집기가 사용할 계정을 선택할 수 있습니다. 이 설명서에서는 사이드바의 컨트롤, 계정 준비, 전환, 사용량 한도, 일상적인 관리 방법을 안내합니다. Claude와 Codex는 서로 독립적으로 관리되므로 한쪽을 전환해도 다른 쪽은 전환되지 않습니다.

아래의 버튼 이름은 한국어 UI 표기를 따릅니다. 아이콘 위에 마우스를 올리면 이름이 표시됩니다. 패널 하단 바닥글의 책 아이콘을 클릭하면 이 설명서가 열립니다.

Claude 계정 옆의 경고 아이콘은 구독 접근이 거부되었음을 뜻합니다. 마우스를 올리면 자세한 내용을 볼 수 있고, 구독을 갱신하거나 접근 권한을 복구한 후 클릭하면 다시 확인합니다. 마지막으로 확인된 플랜은 흐리게 표시되고 이전 사용량 막대는 숨겨지며, 이 계정은 추천되지 않습니다. 확인하는 동안에는 로딩 아이콘이 표시됩니다. 사용량 데이터를 가져올 수 없으면 PlanSwap이 CLI로 최소한의 모델 요청을 자동으로 보낼 수 있으며, 이때 사용량이 조금 소비될 수 있습니다. 사용할 수 없음이 확인된 계정은 다시 확인하거나 확장을 다시 시작할 때까지 자동 확인이 중단됩니다. 네트워크 확인에 실패했다고 해서 구독이 만료된 것은 아닙니다.

## 시작하기 전에

필요한 항목:

- VS Code 1.107 이상과 호환되는 편집기(VS Code, Antigravity IDE 또는 VSCodium). PlanSwap은 WSL 원격 창, 네이티브 Windows, 로컬 Linux 데스크톱 또는 기타 원격 창에서 실행됩니다. macOS는 지원하지 않습니다.
- 해당 창이 실행되는 환경에 설치된 PlanSwap과 공식 Claude Code 확장 및/또는 Codex 확장.
- 선택 사항: 그 환경의 PATH에 있는 `claude` 및/또는 `codex` 명령. 명령을 사용할 수 없으면 터미널에서의 로그인과 사용량 확인에 해당 공식 확장에 포함된 CLI를 사용합니다.
- 네이티브 Windows 외의 환경에서 Codex를 전환하려면: 로그인 셸이 Bash여야 합니다.
- VS Code 또는 VSCodium의 WSL 창에서 Codex를 전환하려면: 창을 연결하는 확장이 WSL 서버가 시작되기 전에 해당 편집기의 `server-env-setup`에 있는 PlanSwap 블록을 읽습니다. VS Code는 Microsoft의 Remote - WSL을 사용하며, VSCodium에는 [wsl-remote](https://open-vsx.org/extension/n2ns/wsl-remote) 확장(`n2ns.wsl-remote`)이 필요합니다.

설정 방법과 각 편집기의 테스트 현황은 [설치 안내](../README.md#install)와 [지원 편집기](../README.md#supported-editors)를 참조하세요.

## 사이드바 살펴보기

작업 막대에서 **PlanSwap**을 클릭한 다음 **Claude** 또는 **Codex** 탭을 선택합니다.

- **기본 계정:** 기존 구성으로, 일반적으로 `~/.claude` 또는 `~/.codex`입니다. Windows에서 `~`는 Windows 사용자 프로필을, WSL에서는 해당 배포판 안의 홈 디렉터리를 뜻합니다. 편집기에서 이미 `CLAUDE_CONFIG_DIR`을 설정했다면 Claude의 기본 디렉터리는 그 값을 따릅니다.
- **이름 있는 계정:** `work`나 `personal` 같은 계정으로, 각각 `~/.claude-work` 또는 `~/.codex-work`처럼 자체 디렉터리를 사용합니다.
- **외부 디렉터리:** 편집기가 현재 사용 중이지만 PlanSwap의 계정 목록에는 없는 디렉터리입니다. PlanSwap에서 이름을 바꾸거나 제거할 수 없습니다.
- **강조 표시된 첫 번째 행:** 현재 계정입니다. Codex에서는 이 창에서 현재 적용된 계정이며, 다시 시작을 기다리는 선택된 계정과 다를 수 있습니다.
- **카드 순서:** 다른 카드를 위아래로 드래그하거나, 카드에 포커스가 있을 때 Alt+↑ / Alt+↓를 눌러 순서를 바꿀 수 있습니다. 현재 계정은 항상 맨 위에 있습니다. 순서는 같은 컴퓨터나 같은 WSL 배포판의 모든 편집기에서 유지되며, 명령 팔레트의 계정 선택 목록에도 사용됩니다.
- **연결 배지:** 연결된 계정을 나타냅니다. 연결된 계정은 기본 계정의 설정, 규칙, Skills, 기록, 세션을 사용합니다. 로그인은 별도로 유지됩니다.

이 설명서에서 사용하는 용어:

- *로그인*과 **로그인** 버튼은 같은 뜻입니다. 로그인하지 않은 행에는 **로그인 안 됨**이 표시됩니다.
- *연결됨*은 UI에서 연결 배지로 표시되는 모드입니다. **기본 계정과 공유**(Share with Default Account) 명령은 독립 계정을 연결된 계정으로 바꿉니다.
- Codex에서 *적용된* 계정은 이 창이 지금 사용하는 계정이고, *선택된* 계정은 다음에 다시 시작한 후 사용할 계정입니다.

각 카드에는 계정의 표시 이름과 로그인 상태가 표시되며, 확인되면 이메일, 플랜, 사용량 한도도 표시됩니다. 아바타에 마우스를 올리면 디렉터리가 표시됩니다.

새로 고침 버튼은 두 종류입니다.

- 패널 제목 표시줄의 새로 고침 버튼은 두 계정 목록을 모두 다시 검색하고 로그인 정보를 다시 불러옵니다.
- **모든 계정** 옆의 아이콘은 사용량 한도를 확인합니다. [사용량 한도 확인 및 새로 고침](#사용량-한도-확인-및-새로-고침)을 참조하세요.

패널 하단의 바닥글은 두 탭 모두에서 항상 표시됩니다. 바닥글 버튼으로 버전 표시, 이 설명서 열기, 창 다시 로드, 확장 호스트 다시 시작, GitHub 저장소 열기를 할 수 있습니다. 버튼 아래에는 설치된 PlanSwap 버전이 표시됩니다.

## 계정 추가 및 로그인

Codex는 먼저 [전환을 활성화](#codex-계정-전환-활성화-및-전환)하세요.

1. 해당 탭에서 **모든 계정** 옆의 **+ 추가**를 클릭합니다.
2. `work` 같은 이름을 입력합니다. 이름 규칙:
   - 영문자, 숫자, 밑줄, 하이픈을 사용합니다.
   - `default`는 예약된 이름입니다.
   - 같은 탭에 있는 다른 계정의 이름이나 표시 이름과 같을 수 없으며, 대소문자는 구분하지 않습니다.
3. 다른 계정으로 같은 작업을 이어서 하려면 **기본 계정에 연결 (추천)** 옵션을 선택한 상태로 두세요. 설정, 기록, 세션이 공유되며 로그인만 분리됩니다. 업무와 개인 작업을 분리하려면 **독립**을 선택하세요. 현재 설정의 복사본으로 시작합니다. 선택하기 전에 [계정 모드](#연결된-계정과-독립-계정-선택)를 확인하세요.
4. **추가**를 클릭하거나 Enter 키를 누릅니다. PlanSwap이 계정 디렉터리를 만들거나, 같은 이름의 기존 디렉터리를 다시 사용합니다. 연결하거나 복사할 수 없었던 파일이 보고되면 목록을 확인하세요. 해당 파일은 그대로 유지됩니다.
5. 새 행에서 **로그인**을 클릭합니다. 터미널이 열리면 그곳에서 공식 클라이언트의 첫 실행 설정과 로그인을 완료합니다. Claude는 대신 해당 계정으로 전환한 후 Claude Code 패널에서 로그인할 수도 있습니다.
6. 행에 계속 **로그인 안 됨**이 표시되면 패널 제목 표시줄의 새로 고침 버튼을 클릭합니다. PlanSwap 터미널을 닫아도 목록이 새로 고쳐집니다.

계정을 추가하거나 로그인해도 편집기가 그 계정을 사용하게 되지는 않습니다. 준비가 되면 그 계정으로 전환하세요. 다른 계정은 로그인 상태가 유지되므로 먼저 로그아웃할 필요가 없습니다. 터미널에서 로그아웃하면 해당 계정 하나의 세션만 종료됩니다. 계정의 이름과 추천 설정은 해당 폴더에 속하므로, 그 폴더에서 다른 계정으로 로그인했다면 필요에 따라 이름을 바꾸거나 전구 아이콘을 다시 클릭하세요.

로그인된 계정에서 터미널 아이콘을 클릭하면 편집기를 전환하지 않고 해당 행의 계정으로 공식 CLI가 열립니다. 터미널 탭 이름은 `Claude (<label>)` 또는 `Codex (<label>)`입니다.

## Claude 계정 전환

1. 현재 계정이 아닌 행에서 **이 계정으로 전환** 화살표 아이콘을 클릭합니다. 카드를 두 번 클릭하거나, Tab 키로 카드에 포커스를 둔 후 Enter 키를 눌러도 됩니다.
2. **전환**을 눌러 확인합니다. 새 Claude 세션은 선택한 계정을 사용합니다. `planswap.claude.confirmSwitch`를 끄면 이 대화 상자 없이 바로 전환됩니다.
3. 배너의 **창 다시 로드**를 클릭하면 열려 있는 Claude 패널이 새 계정으로 옮겨집니다. 기존 세션은 다시 로드할 때까지 이전 계정을 계속 사용합니다.

명령 팔레트의 **Claude 계정: 계정 전환**(Claude Account: Switch Account) 명령은 계정 선택 목록을 표시하고 확인 대화 상자 없이 전환합니다.

전환하면 같은 컴퓨터의 다른 창과 공유되는 편집기 설정이 바뀌므로 그 창들도 함께 전환됩니다. 열려 있는 Claude 세션이 새 계정을 사용해야 하는 창은 각각 다시 로드하세요.

## Codex 계정 전환 활성화 및 전환

### 한 번만 활성화

**Codex** 탭을 열고 **Codex 전환 활성화**를 클릭합니다. 제안된 변경 내용을 검토한 후 확인하세요.

- **WSL, 로컬 Linux 및 기타 원격 창:** PlanSwap이 `~/.profile`과 `~/.bashrc`에 마커 블록을 추가한 다음, Bash 로그인 셸이 선택된 계정을 인식하는지 확인합니다. 충돌하는 `CODEX_HOME` 할당이나 셸 구성이 보고되면 지적된 부분을 수정하고 다시 시도하세요. VS Code 또는 VSCodium의 WSL 창에서는 처음 전환할 때 해당 편집기의 `~/.vscode-server/server-env-setup` 또는 `~/.vscodium-server/server-env-setup`에도 마커 블록을 추가하며, 그 편집기의 WSL 서버는 시작하기 전에 이 파일을 읽습니다.
- **네이티브 Windows:** PlanSwap이 사용자 수준 환경 변수 `CODEX_HOME`을 관리합니다. `CODEX_HOME`을 직접 다른 값으로 설정했다면 활성화가 거부됩니다. 이미 PlanSwap 계정 디렉터리(`~/.codex-<name>`)를 가리키고 있다면 PlanSwap이 관리를 이어받습니다.

Windows의 Codex 확장이 WSL 안에서 실행되도록 설정되어 있다면 WSL 창에서 계정을 관리하거나, Windows 계정을 관리하기 전에 `chatgpt.runCodexInWindowsSubsystemForLinux`를 끄세요. 사이드바 배너와 경고에는 **설정 열기**가 있으며, 클릭하면 설정 편집기에서 해당 설정이 열립니다. PlanSwap이 이 설정을 대신 바꾸지는 않습니다.

### 계정 선택 및 적용

1. 원하는 계정을 추가하고 로그인합니다.
2. 작업을 저장한 다음 해당 계정의 **이 계정으로 전환** 화살표 아이콘을 클릭합니다.
3. 확인 메시지를 읽고 사용 중인 편집기의 다시 시작 안내를 따릅니다.

| 환경 | 선택이 적용되는 방법 |
| --- | --- |
| WSL의 Antigravity 또는 VSCodium | **전환 후 다시 시작**을 눌러 확인합니다. PlanSwap이 편집기의 WSL 서버를 다시 시작하면 연결이 끊어진 각 창에서 **창 다시 로드**를 클릭하세요. 자동으로 다시 시작할 수 없으면 표시되는 수동 안내를 따르세요. |
| WSL의 VS Code | **선택 저장**을 눌러 확인합니다. 해당 배포판에 연결된 VS Code 창을 모두 닫고 몇 초 기다린 다음 다시 여세요. |
| WSL의 기타 편집기 | **선택 저장**을 눌러 확인하고 대화 상자의 수동 다시 시작 안내를 따르세요. |
| 네이티브 Windows | **선택 저장**을 눌러 확인하고 편집기를 완전히 종료한 다음 시작 메뉴나 작업 표시줄에서 다시 시작하세요. 전환 전에 열었던 터미널은 이전 계정을 그대로 사용합니다. |
| 로컬 Linux 또는 기타 원격 창 | **선택 저장**을 눌러 확인합니다. 그런 다음 대화 상자의 안내에 따라 편집기나 원격 서버를 다시 시작하여 선택한 `CODEX_HOME`으로 시작되게 하세요. |

WSL에서 VS Code와 VSCodium은 같은 배포판에서도 각자 선택을 따로 보관하므로, 한 편집기에서 전환해도 다른 편집기의 계정은 바뀌지 않습니다. 통합 터미널은 각자의 편집기를 따릅니다. Antigravity와 편집기 밖에서 연 터미널은 공유 선택을 사용하며, 이 선택은 Antigravity나 인식되지 않는 편집기에서 전환할 때만 바뀝니다.

WSL 서버를 다시 시작하면 해당 편집기 창의 연결이 끊어지고 통합 터미널과 CLI 세션이 닫힙니다. **창 다시 로드**나 **확장 호스트 다시 시작**만으로는 Codex 계정 선택이 적용되지 않습니다.

다시 시작이 완료될 때까지 배너에 선택된 계정이 표시되며, 강조 표시된 행은 여전히 이 창에서 현재 적용된 계정입니다. 다시 시작 단계를 다시 보려면 명령 팔레트에서 **Codex 계정 적용: 다시 시작 또는 안내 표시**(Apply Codex Account: Restart or Show Instructions, **Codex 계정** 아래에 표시됨)를 실행하세요.

다시 시작하기 전에 마음이 바뀌었나요? 강조 표시된(적용된) 행의 화살표 아이콘을 클릭하세요. 대기 중인 선택이 취소되며 다시 시작할 필요가 없습니다.

## 연결된 계정과 독립 계정 선택

| 내용 | 연결된 계정 | 독립 계정 |
| --- | --- | --- |
| 설정, 규칙, Skills | 기본 계정의 것을 사용 | 복사본으로 시작하며 이후 편집은 별도로 유지 |
| 프롬프트 기록과 세션 | 기본 계정의 것을 사용 | 자체적으로 보관 |
| 로그인 | 별도 | 별도 |
| Codex Memories | 별도 | 별도 |
| Codex 스레드 데이터베이스 | WSL과 Linux에서는 공유, 네이티브 Windows에서는 별도 | 별도 |

연결해도 다른 계정이 세션을 이어서 진행할 수 있다고 보장되지는 않으며, 특히 ChatGPT 조직이 다르면 더욱 그렇습니다. 같은 세션을 두 계정에서 동시에 열지 마세요.

일부 설정은 연결되지 않습니다. Claude: 로그인을 제공하거나 제한하는 `settings.json`(예: API 키, API 키 도우미, 강제 로그인 방법)은 연결되지 않으며, 계정은 그 설정을 제외한 자체 사본을 받고 이 사본은 이후 변경 내용을 따르지 않습니다. Codex: `forced_login_method`나 `forced_chatgpt_workspace_id`(로그인 방식이 다른 계정을 로그아웃시킴) 또는 지원되지 않는 `sqlite_home`을 설정한 `config.toml`은 연결되지 않으며, 그 설정을 제거하고 **다시 연결**을 사용할 때까지 계정은 Codex 기본 제공 설정으로 실행됩니다. 결과 메시지에는 해당 파일과, Codex의 경우 해당 설정이 표시됩니다. 한 줄짜리 `sqlite_home = "."`(또는 `"./"`처럼 점으로만 이루어진 동등한 값)은 허용됩니다. 이 경우 각 계정은 자기 디렉터리를 SQLite 경로의 기준으로 사용하며, 기존 데이터베이스 공유 규칙은 그대로 유지됩니다. 다른 값은 계속 지원되지 않으므로 설정을 제거하거나 `"."`을 사용한 다음 **다시 연결**을 사용하세요.

연결된 Claude 계정은 MCP 서버, 신뢰 설정 같은 프로젝트별 설정, MCP 서버 인증(예: Stripe 또는 Notion 인증)도 기본 계정과 공유합니다. 전환할 때마다 떠나는 계정과 여는 계정을 기본 계정과 양방향으로 동기화하므로, 어느 연결된 계정에서든 또는 기본 계정에서 직접(예: PlanSwap 밖의 터미널에서 `claude mcp add` 실행) 추가, 변경, 제거한 서버가 모든 연결된 계정에 반영되고, 한 계정에서 인증한 MCP 서버를 다른 계정에서도 쓸 수 있습니다. 마지막 동기화 이후 양쪽에서 같은 서버나 설정을 바꿨다면 계정 쪽 내용이 우선합니다. 한 계정에서 MCP 인증을 지워도 다른 계정에서는 삭제되지 않으며, 다음 전환 때 다시 돌아옵니다. Claude 로그인은 계정마다 따로 유지됩니다. 계정에 로그인하면 기본 계정의 첫 실행 상태도 복사하므로 Claude Code가 첫 실행 설정을 반복하지 않습니다. 동기화에 실패하면 전환이 취소되고 메시지에 이유가 표시됩니다. **다시 연결**은 사용 중인 계정에 기본 계정보다 부족한 항목도 보고합니다. 이미 실행 중인 세션은 새 세션을 시작해야 변경이 반영됩니다.

### 기존 계정의 모드 변경

계정을 변환하기 전에:

1. 다른 계정으로 전환합니다. Codex는 다시 시작까지 완료하여 해당 계정이 적용된 계정도 선택된 계정도 아닌 상태로 만드세요.
2. 해당 계정의 세션과 PlanSwap 터미널 탭을 닫습니다.

그런 다음:

- **기본 계정에 연결:** 독립된 이름 있는 계정 행에서 연결 아이콘을 클릭하거나, 해당 제품의 **기본 계정과 공유** 명령을 실행합니다. 계정 자체의 설정과 기록이 기본 계정으로 이동합니다. 기본 계정과 내용이 다른 파일은 직접 병합할 수 있도록 나란히 보관되며 결과에 목록으로 표시됩니다.
- **기본 계정과 연결 해제:** 연결된 이름 있는 계정 행에서 연결 해제 아이콘을 클릭합니다. 계정은 기본 구성의 자체 복사본을 받고, 로그인과 연결되지 않았던 파일은 그대로 유지합니다. 기록과 세션은 기본 계정에 남으며 다시 복사되지 않습니다. 연결을 해제해도 연결할 때 수행된 병합은 되돌려지지 않습니다.
- **다시 연결:** 기본 계정의 설정을 바꾼 후나 링크를 복구해야 할 때 **도구**에서 **다시 연결**을 클릭합니다. 먼저 해당 탭의 모든 연결된 계정을 아무것도 바꾸지 않고 검사합니다. 문제가 없으면 그렇다고 알려 주며, 다른 곳을 가리키도록 바꾼 링크나 계정 자체 파일처럼 의도적으로 또는 계정에 의해 그대로 둔 항목을 나열합니다. 문제가 있으면 누락된 링크나 사용 중인 계정 같은 문제를 계정별로 하나의 알림에 나열합니다. **복구**를 클릭하면 고칠 수 있는 항목을 고치며, 기본 계정의 내용은 덮어쓰지 않습니다. Claude의 경우 기본 계정에 새로 생겼지만 연결된 계정(사용 중인 계정 포함)에는 없는 MCP 서버, 신뢰된 프로젝트, MCP 인증도 검사하며, **복구**가 이를 추가합니다. Claude에서 복구는 해당 알림에 나열된 계정과 항목만 변경하며 계정이 직접 바꾼 내용은 유지합니다. `tasks`, `uploads` 같은 선택적 대상이 없는 것은 문제로 보고하지 않으며, 계정을 추가하거나 전환할 때 준비됩니다. 이전 버전의 `todos`는 더 이상 검사하거나 만들지 않으며, 기존 데이터는 유지됩니다. 없는 기록 대상을 빈 상태로 만들어도 이전 내용은 복원되지 않습니다. Claude는 사용하지 않는 기본 대상이 없을 때 계정 자체의 기록 디렉터리를 참고 항목으로 유지하며, 정상적으로 만료된 플러그인 설치 백업은 무시합니다. Codex에서 선택적 `themes` 디렉터리가 없어도 복구 경고는 표시되지 않지만, 기존 테마에는 여전히 올바른 링크가 필요합니다.
- **자동 검사:** PlanSwap은 편집기가 시작될 때와 편집기 창으로 돌아올 때(최대 10분에 한 번) 같은 검사를 백그라운드에서 실행합니다. **복구**로 고칠 수 있는 항목이 있을 때만 알림을 표시합니다. 사용 중인 계정, 다른 곳을 가리키도록 바꾼 링크, 기본 계정에서만 신뢰된 프로젝트는 **다시 연결**을 클릭했을 때만 나열되며, 해당 계정으로 전환하면 그 신뢰 설정은 어차피 복사됩니다. 스스로 복구하지는 않습니다. 같은 문제는 편집기 창을 여러 개 열어 두어도 한 번만 표시되며, 하루가 지난 후에도 남아 있으면 다시 표시됩니다.

### Windows에서의 연결

- 연결된 디렉터리에는 디렉터리 정션을 사용하므로 추가 권한이 필요하지 않습니다.
- 개별 파일을 연결하려면 Windows 개발자 모드를 켜거나 편집기를 관리자 권한으로 실행해야 합니다. 그렇지 않으면 PlanSwap은 대신 작은 구성 파일을 한 번만 복사하도록 제안하며, 이후 이 사본을 편집한 내용은 별도로 유지됩니다.
- 나중에 제대로 연결하려면 **개발자 설정 열기**를 선택하고 개발자 모드를 켠 다음 **다시 연결**을 클릭하세요. 누락된 링크가 만들어지고 변경되지 않은 사본은 링크로 바뀝니다.
- PlanSwap이 복사 여부를 묻는 동안 해당 계정의 PlanSwap 터미널이 열리면 변환은 아무것도 바꾸지 않고 중단됩니다. 터미널을 닫고 다시 시도하세요.
- Windows에서는 SQLite가 링크를 통해 쓴 데이터를 잃을 수 있으므로 Codex 스레드 데이터베이스(`*.sqlite`)는 연결하지 않습니다. 각 계정이 자체 데이터베이스를 보관하며, 세션, 기록, 구성은 계속 공유됩니다.
- Windows에서 PlanSwap은 실행 중인 Claude 또는 Codex 프로세스가 어느 계정에 속하는지 알 수 없습니다. 계정을 연결하거나 연결 해제하거나 제거하기 전에, CLI가 이미 종료되었더라도 해당 계정의 세션과 PlanSwap 터미널 탭을 닫으세요.

## 사용량 한도 확인 및 새로 고침

사용량 막대와 비율은 **남은 양**을 표시합니다. 사용한 양을 표시하려면 [설정](#언어-및-표시-설정-변경)에서 `planswap.usageDisplay`를 `used`로 설정하세요. 각 한도 옆의 `2일 5시간` 같은 기간은 초기화까지 남은 시간입니다. 막대에 마우스를 올리면 두 값이 모두 표시됩니다(예: `97% 남음 (3% 사용)`). 남은 양이 30% 이하이면 막대가 노란색으로, 10% 이하이면 빨간색으로 바뀌며, 사용한 양을 표시할 때도 마찬가지입니다. 이 기준은 `planswap.usageWarningThreshold`와 `planswap.usageErrorThreshold`로 바꿀 수 있습니다. 모두 사용한 한도는 비율과 초기화 시간이 빨간색으로 표시됩니다. 사용량 줄이 없으면 아직 데이터가 없다는 뜻이며, 사용량이 0이거나 한도가 무제한이라는 뜻이 아닙니다.

사용량 확인에는 Claude 구독 로그인 또는 Codex ChatGPT 로그인(API 키 모드 제외)이 필요합니다. 확인은 공식 CLI를 실행하여 이루어집니다.

### 사이드바에서 새로 고침

**모든 계정** 옆의 아이콘:

- **현재 계정의 사용량 한도 새로 고침**(새로 고침 아이콘): 현재 Claude 계정 또는 적용된 Codex 계정을 확인합니다. 해당 계정을 확인할 수 있을 때 표시됩니다.
- **모든 계정의 사용량 한도 새로 고침**(겹쳐진 레이어 아이콘): 해당 탭에서 로그인된 모든 계정을 하나씩 확인하므로 전환하기 전에 비교할 수 있습니다. 각 행은 확인이 끝나는 대로 업데이트됩니다. 계정을 전환하지 않으며, 진행률 알림에서 취소할 수 있습니다. 목록에 확인할 수 있는 계정이 하나 이상 있을 때 표시됩니다.

Codex 탭에서는 Codex 전환이 비활성화되어 있거나, Windows에서 Codex가 WSL 안에서 실행되는 동안에는 두 아이콘 모두 표시되지 않습니다.

명령 팔레트에도 같은 작업이 있습니다: **Claude 사용량 한도 새로 고침**, **모든 Claude 계정의 사용량 한도 새로 고침**, **Codex 사용량 한도 새로 고침**, **모든 Codex 계정의 사용량 한도 새로 고침**.

1분 이내에 확인한 계정은 다시 확인하지 않습니다. 이때 수동으로 새로 고치면 "사용량 한도를 확인한 지 1분이 지나지 않았습니다. N초 후에 다시 시도하세요."라는 메시지가 표시됩니다. 자동 확인을 포함한 모든 확인이 해당되며, Claude의 경우 다른 창이나 터미널에서 한 확인도 포함됩니다. 모두 새로 고침은 이러한 계정을 건너뛰고 건너뛴 계정 수를 알려 줍니다.

### 자동 확인

기본적으로 자동 확인은 각 제품에서 조건을 충족하는 로그인된 계정을 대상으로 하며, 현재 Claude 계정 또는 현재 적용된 Codex 계정을 먼저 확인한 다음 등록된 다른 계정을 하나씩 확인합니다. 첫 확인은 활성화 후 약 20초 뒤에 이루어집니다. 창에 포커스가 있는 동안 스케줄러는 기본적으로 120초마다 확인할 때가 된 계정을 찾으며, 계정마다 15분을 기준으로 데이터가 최신인지 판단합니다. 조회는 대기열에서 기다릴 수 있고 캐시가 최신이면 조회를 건너뛸 수 있으므로, 정확히 15분마다 실행되는 일정은 아닙니다. 대상 계정 범위를 제한하려면 `planswap.usageAutoRefreshCurrentOnly`를 켜고, 간격과 자동 확인 스위치는 [설정](#언어-및-표시-설정-변경)에서 바꾸세요.

다른 행에는 마지막 확인 결과가 표시됩니다. 값은 초기화 시간이 지나거나 24시간이 지나면 사라지며, 그 이후 계정에 다시 로그인한 경우에는 숨겨집니다.

### 추천 계정

현재 계정의 일반 한도 중 가장 낮은 남은 비율이 `planswap.sidebar.recommendationThreshold`(기본값 10%) 이하가 되면, 목록 위에 녹색 카드가 나타나 같은 탭에서 로그인된 다른 계정을 추천합니다. 추천 대상은 가장 낮은 한도의 남은 양이 가장 많은 계정으로, 현재 계정보다 남은 양이 많고, 모두 사용한 한도가 없으며, 현재 계정과 같은 계정으로 로그인되어 있지 않아야 합니다. 카드에는 그 계정의 한도와 마지막 확인 이후 경과 시간이 표시되며, **전환** 및 **터미널** 버튼은 해당 계정 카드의 버튼과 같은 동작을 합니다(Claude: 평소와 같은 확인 절차가 이어짐, Codex: 계정이 선택되고 편집기 서버 다시 시작이 이어짐). Codex 탭에서는 선택된 계정이 서버 다시 시작을 기다리는 동안 카드가 표시되지 않습니다. 모델별 한도는 비교하지 않으며, 카드 자체는 아무것도 조회하지 않으므로 수치는 해당 계정의 마지막 확인 시점 기준입니다.

업무용 계정처럼 추천에서 제외하려는 계정이 있으면 해당 카드의 전구 아이콘을 클릭하세요. 다시 클릭하면 추천에 포함됩니다. 카드와 전구 아이콘을 숨기려면 [설정](#언어-및-표시-설정-변경)에서 `planswap.sidebar.showRecommendation`을 끄세요.

구독을 사용할 수 없는 Claude 계정에서는 전구 아이콘이 숨겨지지만, 추천 포함 또는 제외 설정은 바뀌지 않습니다. 접근 권한이 복구되면 일반적인 표시 조건을 충족할 때 다시 나타납니다.

### 상태 표시줄

상태 표시줄에는 각 제품의 짧은 한도가 표시됩니다(예: `Claude 97% · Codex 82%`). 남은 양이 표시되며, `planswap.usageDisplay`가 `used`이면 사용한 양이 표시됩니다. 더 긴 한도가 부족해지고 있으면 그 한도를 길이와 함께 대신 표시합니다(예: `Claude 2% (7일)`). 그 수치는 며칠이 지나야 회복되기 때문입니다. 더 긴 한도를 포함해 일반 한도 중 하나라도 30% 이하가 되면 배경이 테마의 경고 색상으로, 10% 이하가 되면 오류 색상으로 바뀝니다. 이 임계값을 바꾸거나, 한 제품만 표시하거나, 항목을 왼쪽으로 옮기거나 숨길 수 있습니다([언어 및 표시 설정 변경](#언어-및-표시-설정-변경)).

마우스를 올리면 제품마다 머리글 행 하나(이메일, 플랜, 그리고 확인할 수 있는 계정이면 새로 고침 아이콘)와 일반 한도마다 행 하나로 이루어진 표가 표시됩니다. 클릭하면 PlanSwap이 열립니다. `planswap.sidebar.showEmail`을 끄면 도구 설명에 이메일 대신 계정 레이블이 표시되며, 사용자가 정한 이름과 별칭은 바뀌지 않습니다.

## 계정 이름 바꾸기 및 제거

### 표시 이름 변경

이름 있는 계정에 마우스를 올리거나 포커스를 둔 다음 이름 옆의 연필 아이콘을 클릭합니다. 표시 이름을 입력한 후 Enter 키를 누르거나, 확인 표시를 클릭하거나, 다른 곳을 클릭하면 저장되며, Esc 키를 누르면 취소됩니다.

표시 이름에는 공백을 포함할 수 있고 최대 32자까지 입력할 수 있으며, 해당 탭에 있는 다른 계정의 이름이나 표시 이름과 같을 수 없습니다. 이름을 바꿔도 디렉터리나 로그인은 바뀌지 않습니다. 기본 계정 행과 외부 디렉터리 행은 이름을 바꿀 수 없습니다.

### 계정 제거

1. 먼저 다른 계정으로 전환합니다. Codex는 다시 시작까지 완료하여 해당 계정이 적용된 계정도 선택된 계정도 아닌 상태로 만드세요. 해당 계정의 세션과 터미널을 닫으세요.
2. 휴지통 아이콘을 클릭하고 행에서 **제거**를 눌러 확인하거나, 명령 팔레트에서 해당 제품의 삭제 명령을 사용합니다.
3. 두 번째 대화 상자에서 계정 디렉터리도 삭제할지 묻습니다.

디렉터리를 유지하면 목록 항목과 표시 이름만 제거됩니다. 같은 이름을 다시 추가할 때까지 PlanSwap은 이 계정을 찾지 않습니다.

디렉터리를 삭제하면 로그인 정보와 그 안에 저장된 모든 내용이 영구적으로 삭제됩니다.

- 연결된 계정의 경우 기본 계정에 있는 데이터는 유지되며, 계정 자체의 로그인 정보, 백업, 연결되지 않은 기타 파일은 삭제됩니다. Codex에서는 계정의 Memories도 포함됩니다.
- 계정이 사용 중이어서 PlanSwap이 거부하면 안내된 세션이나 프로세스를 닫고 다시 시도하세요.

PlanSwap이 홈 디렉터리에서 찾은 올바른 이름의 계정 디렉터리는 시작하거나 새로 고칠 때 자동으로 목록에 추가됩니다.

패널 제목 표시줄의 설정 아이콘을 클릭하거나 **PlanSwap: PlanSwap 설정 열기**(PlanSwap: Open PlanSwap Settings)를 실행하세요. 설정 편집기에서는 일반, 사이드바, 상태 표시줄, 계정, 고급 그룹으로 나뉘며, 아래 표도 같은 순서를 따릅니다. 설정을 찾으려면 표에 있는 설정 이름을 설정 검색 상자에 입력하세요. 변경 사항은 즉시 적용됩니다.

| `planswap.codex.usageRefreshMinutes` | `15` | Codex: 캐시된 사용량 또는 마지막 확인 이후 자동 새로 고침 대상이 되기까지의 시간(분)입니다. 자동 새로 고침을 켜야 하며, 정확한 실행 일정은 아닙니다. 범위: 5–1440. |
| `planswap.usageCheckIntervalSeconds` | `120` | 자동 새로 고침 시점이 된 계정을 확인하는 간격(초)입니다. 각 계정의 새로 고침 주기는 '계정' 그룹에서 설정합니다. 범위: 30–600. |
| `planswap.claude.usageTimeoutSeconds` | `30` | Claude: 사용량 조회가 시간 초과되기까지의 시간(초)입니다. 자동 새로 고침과 수동 새로 고침 모두에 적용됩니다. 범위: 10–120. |
| `planswap.codex.usageTimeoutSeconds` | `15` | Codex: 사용량 조회가 시간 초과되기까지의 시간(초)입니다. 자동 새로 고침과 수동 새로 고침 모두에 적용됩니다. 범위: 5–120. |

자동 확인을 꺼도 새로 고침 아이콘과 명령은 계속 작동합니다. 이메일 설정은 상태 표시줄 도구 설명에도 적용됩니다. 색상은 일반 그룹의 공통 임계값을 사용하며, 추천과 사이드바 한도 표시 설정은 상태 표시줄에 영향을 주지 않습니다. 명령 팔레트 제목과 사이드바 이름은 `planswap.language`가 아니라 편집기의 표시 언어를 따릅니다.

## 일반적인 문제 해결

| 증상 | 확인할 사항 |
| --- | --- |
| Claude가 여전히 이전 계정을 사용함 | 창을 다시 로드하여 열려 있는 Claude 패널을 새 계정으로 옮기세요. 환경의 자격 증명이나 공급자 설정이 계정의 로그인보다 우선한다는 PlanSwap 경고가 있는지 확인하세요. |
| Codex에 대기 중인 선택이 표시됨 | 사용 중인 환경에 맞는 다시 시작을 완료하세요. 창을 다시 로드하는 것은 편집기나 WSL 서버를 다시 시작하는 것을 대신하지 않습니다. |
| Codex 전환을 활성화할 수 없음 | 표시된 셸 또는 `CODEX_HOME` 충돌을 확인하세요. Windows에서는 Codex가 WSL 안에서 실행되도록 설정되어 있는지 확인하세요. |
| 계정에 계속 **로그인 안 됨**이 표시됨 | 해당 행의 **로그인** 버튼으로 로그인한 다음 새로 고치세요. PlanSwap은 계정의 `auth.json`을 찾으므로, 운영 체제 키링에만 보관된 Codex 로그인은 감지할 수 없습니다. |
| 두 계정에서 중복 로그인 경고가 표시됨 | 두 계정이 같은 계정과 워크스페이스로 로그인되어 있으므로, 둘 사이에서 전환해도 한도가 따로 적용되지 않습니다. 둘 중 하나에서 원하는 계정으로 로그인하세요. |
| 사용량 막대가 없거나 확인에 실패함 | 계정이 구독(Claude) 또는 ChatGPT(Codex)로 로그인되어 있는지, 그리고 `claude` 명령이나 공식 Claude Code 확장이 설치되어 있는지(Claude) 확인하세요. 직접 새로 고친 후 실패 메시지를 읽고, 대기 시간이 표시되면 잠시 기다린 후 다시 시도하세요. CLI가 제시간에 응답하지 않았다는 메시지가 나오면 `planswap.claude.usageTimeoutSeconds` 또는 `planswap.codex.usageTimeoutSeconds` 값을 늘리세요. |
| 설정이나 기록이 예상대로 공유되지 않음 | 연결 배지와 변환 또는 다시 연결 결과를 확인하세요. 일부 파일은 별도로 유지되거나 직접 병합해야 합니다. Windows에서는 파일 링크를 사용할 수 있는지 확인하세요. |
| 목록이 오래된 것 같음 | 패널 제목 표시줄의 새로 고침 버튼을 클릭하세요. 다른 창에서 변경한 내용은 새로 고친 후에 나타납니다. |

### 모든 계정에 적용되는 로그인

다음 항목은 각 계정 자체의 로그인보다 우선하므로, 이 중 하나라도 설정되어 있으면 Claude 계정을 전환해도 효과가 없습니다. PlanSwap은 환경에서 이러한 항목을 발견하면 경고합니다.

- API 키, 인증 토큰 또는 장기 OAuth 토큰: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`
- 이름 있는 Anthropic 프로필(`ANTHROPIC_PROFILE`) 또는 페더레이션 변수(`ANTHROPIC_FEDERATION_RULE_ID`와 `ANTHROPIC_ORGANIZATION_ID`)
- 클라우드 공급자 설정: `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`

API 키 없이 로그인한 Claude Console 로그인은 계정 디렉터리 밖(`~/.config/anthropic`, Windows에서는 `%APPDATA%\Anthropic`)에 저장되며 컴퓨터의 모든 claude.ai 로그인을 로그아웃시키므로 계정별로 유지할 수 없습니다([Claude Code 인증](https://code.claude.com/docs/en/authentication#sign-in-without-an-api-key)).

### Windows의 OneDrive

사용자 폴더가 OneDrive로 동기화되고 있으면 PlanSwap이 경고합니다. OneDrive 동기화는 Claude Code의 `.claude.json`을 손상시키는 것으로 알려져 있으며, 모든 계정 디렉터리가 이 폴더 안에 있습니다.

다른 계정의 세션을 이어서 진행하는 것과 같은 기타 제한 사항은 [알려진 제한 사항](../README.md#known-limitations)을 참조하세요. PlanSwap이 읽고, 저장하고, 전송하는 내용은 [개인정보 보호](privacy.md)를 참조하세요.

## 전환 비활성화 및 확장 제거

1. Claude를 `default`로 다시 전환하고 창을 다시 로드합니다.
2. Codex 전환이 활성화되어 있다면 **Codex 계정 전환 비활성화**(Disable Codex Account Switching, 명령 팔레트의 **Codex 계정** 아래)를 실행하고 확인합니다. 이렇게 하면 `~/.profile`, `~/.bashrc` 및 각 편집기의 `server-env-setup`에 있는 PlanSwap 마커 블록(Windows에서는 사용자 수준 `CODEX_HOME`)이 제거되고 선택이 지워집니다. 열려 있는 창은 [계정 선택 및 적용](#계정-선택-및-적용)에 설명된 대로 다시 시작할 때까지 이전 계정을 사용합니다.
3. 원하면 확장 보기에서 PlanSwap을 제거합니다.

계정 디렉터리는 유지됩니다. PlanSwap이 저장한 계정 목록, 표시 이름, 사용량 기록도 지우려면 [제거 안내](../README.md#uninstall)를 참조하세요. 이 작업은 계정 자체 파일을 건드리지 않습니다.
