# Antigravity CLI (agy): research record

Facts about the Antigravity CLI (`agy`) that the [agy design](../agy-design.md) rests on, each with the version and source it was read from or verified with. "Fact N" in the agy design refers to the numbered list below. **Re-verify these facts after upgrading agy.**

## Facts

Sources: agy 1.5.10 on WSL (Ubuntu), checked on 2026-11-17 with `agy --version`, `agy --help`, `agy changelog`, a read-only `/usage` query and file metadata (names, modes and JSON key names only; no credential value was printed); the go-keyring storage and the macOS / Windows encodings from the source of two third-party switchers, `farion1231/cc-switch` (`src-tauri/src/services/agy_account/keychain.rs`, `mod.rs`, tree `d243d970af87e13a243b005d6af73d0375050486`, which records a real-machine check on macOS) and `fikrilal/agy-auth` (`internal/agy/storage.go`, `token.go`, tree `d44bfdf8a1fc7c7a42d92f9c72516d25c686672b`).

1. agy keeps one global sign-in; `agy --help` (1.5.10) has no option or subcommand that selects an account, profile or credential folder. Signing in to another Google account is done inside agy with `/logout` and `/login` (changelog). (Runtime, WSL.)
2. The sign-in is one JSON document: `token.{access_token, token_type, refresh_token, expiry, expires_in}`, `auth_method` (`consumer` here) and either `id_token` (older agy) or `id_token_email` (agy 1.5 and later); optional `project_id`, `region`, `user_tier`, `tier_display_name`. (Key names read on WSL; the rest from both sources.)
3. agy stores it with go-keyring (service `gemini`, user `antigravity`) and falls back to the file `~/.gemini/antigravity-cli/antigravity-oauth-token` when the keyring is unavailable (agy-auth `storage.go`; agy changelog: "/logout ... short-circuiting token removal directly to file storage when keyring storage is bypassed or unreachable"). On this WSL the file exists with mode 600 while the Secret Service (gnome-keyring, `org.freedesktop.secrets` owned on the session bus) holds no item for that service and user (`SearchItems` returned empty lists), so agy 1.5.10 uses the file here. (Runtime, WSL.) go-keyring reaches the Secret Service through the godbus library (`dbus.SessionBus()` in `secret_service/secret_service.go`, zalando/go-keyring master `66b55cc0c51cd3d8dabc0ac70da30f058b2fe54a`, source inspection), not through a `gdbus` program, so whether `gdbus` is installed says nothing about where agy keeps its sign-in. godbus finds the session bus from `DBUS_SESSION_BUS_ADDRESS`, otherwise by uid regardless of `XDG_RUNTIME_DIR`: the socket `/run/user/<uid>/bus`, then the `DBUS_SESSION_BUS_ADDRESS=` line of `/run/user/<uid>/dbus-session`, and with neither `SessionBus()` autolaunches a bus through `dbus-launch` when that is installed (`ConnectSessionBus` calls `getSessionBusAddress(true)`; `conn.go`, `tryDiscoverDbusSessionBusAddress` in `conn_other.go`, godbus/dbus v5.2.4, source inspection).
4. macOS: the item is a generic password in the login Keychain read and written through `/usr/bin/security`, whose value is `go-keyring-base64:` followed by the base64 of the JSON; `security -i` reads commands from stdin in lines of at most 4096 bytes and may exit 0 after an error reported only on stderr; `find-generic-password` exits 44 when the item is missing. (cc-switch source and its recorded real-machine check; not verified here.)
5. Windows: the item is a generic credential in the Credential Manager with target `gemini:antigravity` and user `antigravity`, whose blob is the bare JSON as UTF-8, at most 2560 bytes; agy 1.5 writes `id_token_email` instead of `id_token` partly for this limit. (cc-switch source; agy changelog on oversized enterprise sign-ins; not verified here.)
6. `agy -p "/usage" --output-format json` answers the read-only slash command "without starting an agent turn, spending quota, or leaving a conversation behind" (changelog). Its payload (exit 0 on WSL) is `command.data.groups[]` with `name`, `description` and `buckets[]` of `{id, name, description, window ('5h' | 'weekly'), remaining_fraction, reset_time (UTC ISO)}`; groups seen: "Gemini Models" and "Claude and GPT models". It names no account. (Runtime, WSL.)
7. The agy installer puts the binary in `~/.local/bin/agy` on Linux. (Runtime, WSL.)
8. Antigravity's FAQ says automatic account rotation and third-party wrappers are not supported for consumer plans (https://antigravity.google/docs/faq). (Documentation; reason PlanSwap switches only on the user's request.)
9. Other switchers leave running agy processes alone: agy-auth's `switch` writes the keyring and its file mirror and tells the user to restart, and cc-switch only shows a notice after a successful switch when agy is running. A running agy that renews its tokens may write the previous account's sign-in back; this was not reproduced here. (Source inspection.)
10. agy keeps its configuration under `~/.gemini` on macOS as on Linux: on a Mac where agy 1.5.17 had never run, its first run created `~/.gemini/config/` (`config.json`, `mcp_config.json`, `projects/`) and `~/.gemini/antigravity-cli/`. The only file it wrote under `~/Library/Application Support` was `antigravity/credential-user-scope` (17 bytes, mode 600, created at the first sign-in; contents not read). Its built-in documentation names `~/.gemini/antigravity-cli/settings.json` as the CLI's settings file; agy had not created that file before the first interactive session on that Mac, and wrote it then (mode 600, at the same minute as the sign-in, holding only `trustedWorkspaces`). (Runtime, macOS 26.7.3 and WSL, 2026-11-26.) Windows not verified.
11. agy's global rules are `~/.gemini/GEMINI.md`, `~/.gemini/AGENTS.md`, their `~/.gemini/config/` counterparts and the `~/.gemini/config/rules/` folder (agy's built-in changelog: "global rules … when `~/.gemini/GEMINI.md`, `~/.gemini/AGENTS.md`, or their `~/.gemini/config/` counterparts are symlinks to the same file"; "global rules and customization files in `~/.gemini/config`, including the `rules/` folder"). agy creates none of them. How they rank when several exist was not checked. (agy 1.5.17 binary strings, macOS.)
12. `agy update` updates the CLI (`agy --help`: "update  Update CLI", 1.5.17 on macOS and 1.5.18 on WSL). (Runtime, help text only; no update was run.)
