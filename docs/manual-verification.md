# Manual Verification

Purpose: acceptance procedures and expected observations for the sidebar and account flows. These are checklists, not evidence that a check has passed. Product behavior belongs in [Features](features.md); pending checks remain in [TODO](../TODO.md). Build and package instructions are in [Development](development.md).

## Preview verification

Every frontend change must be checked in the preview page at sidebar/container widths **200, 240, 280, 340 and 420px**, in English, Simplified Chinese, Spanish and Japanese. There must be no horizontal scroll bar; names, emails, directories, version values and banner text must wrap or be ellipsized; button groups must not overlap text. Check that the tag group stays beside the name whenever it fits and wraps under it, right-aligned, only when it does not and include screenshots and assertions in the report.

Use a headless browser (the default of `npm run test:ui`, or a headless browser for manual preview checks); do not open a browser window on the user's display. Keep 100% zoom with a fixed viewport (a headed browser, only when explicitly requested, stays full-screen). Adjust the sidebar or preview container width, not the browser viewport or page zoom.

During preview verification, every agent (the main agent and each subagent independently) opens exactly one browser tab for the task and reuses it with `navigate_page` (reload or change URL parameters). Do not share tabs between agents or call `new_page` repeatedly. Include this rule in any delegated frontend verification task. When finished, close the tab you opened and stop the preview static server by its PID. Never kill processes by name; only clean up processes started for the current task.

For the repeatable fixture page and automated checks, see [Development: Repeatable Webview checks](development.md#repeatable-webview-checks). The runner saves screenshots and JSON assertions under `.test-out/ui/`; review those artifacts as well as the exit status.

A static preview verifies layout, not the real editor integration or account switching. Report those checks separately. The real-account steps below are performed by the user; a preview does not authorize writing account data or restarting a WSL server.

## WSL setup and safety

### Command Palette sharing

For each provider, prepare an independent named test account that is not current (and, for Codex, not selected). Run **Share with Default Account** from that provider's Command Palette category. Check that the picker uses aliases and excludes default, external, already shared and in-use selections. Cancel the picker, then repeat and cancel the conversion modal: account files must remain unchanged. Confirm on a disposable account to exercise the same conversion and busy checks as the sidebar sharing procedures below. With no eligible accounts, expect **No accounts to choose from.** Verify the command title and picker prompt in English, Simplified Chinese, Spanish and Japanese. Real-account conversion remains user-operated.

### Setup

`npm test` covers modules and mocked host interactions, not a real Webview; for changes affecting UI behavior, verify the affected flows manually in a **WSL window**. Two ways:

- **Install the vsix**: `npm run package`, then in the WSL window run `Extensions: Install from VSIX...`, install and reload.
- **Extension Development Host**: open this repository in a WSL window and press F5 (the "Run Extension" configuration). `.vscode/tasks.json` runs `npm run build` first and then starts the Extension Development Host window. For frontend problems run `Developer: Open Webview Developer Tools` in the development host to see the console (e.g. CSP errors). If the vsix of this extension is installed, disable it in the development host first to avoid duplicate command and view registrations. If F5 never attaches (VS Code 1.139, "Could not connect to debug target"), see [Development: F5 troubleshooting](development.md#1-f5-does-not-load-the-extension-in-vs-code-1139-js-debug-attach-regression).

3. **CLI missing**: start the editor with `codex` removed from PATH but the Codex extension (`openai.chatgpt`) installed and hover: the usage lines still appear (answered by the extension's bundled binary). Then also disable or uninstall the Codex extension, restart the editor and hover: "Usage check failed" appears; no retry loop (at most one attempt per 15 minutes while focused).
4. **Sign-in tip**: open the terminal of a signed-out Claude account and click "Log in" on a signed-out Codex row; each shows the tip that other accounts stay signed in.
5. **Duplicate sign-in**: sign two throwaway accounts of one vendor in to the same account and workspace/organization; the `identity.duplicate` warning names both, once per window session. The same email in two different workspaces produces no warning.

### Claude usage limits

Performed by the user with real Claude subscription accounts ([Claude design 6.9](design.md#69-claude-usage-limits), [Features](features.md#claude-usage-limits)). Never record emails, tokens, account identifiers or raw CLI output.

1. **Tooltip values**: with a signed-in subscription account current, hover the PlanSwap status bar item: the Claude rows start with a header row of the email (bold, left) and plan (right), then one row per general limit window with its bar directly next to its name (no wide gap after "5h"; the bars line up with Codex's) (session and weekly, shortest first) with a remaining bar, remaining percentage and relative reset time; it has no account name, directory, "Checked" time or links. Model-specific windows do not appear in the tooltip. Toggle `planswap.sidebar.showModelLimits`: the sidebar immediately shows or hides the model-specific windows below the general ones, never folded (default off), while general windows and the status bar stay unchanged. The values match `claude -p "/usage"` run in a terminal for the same account (no `CLAUDE_CONFIG_DIR` for the default account) at about the same time; allow for the one-minute cache and rounding. The same values appear on the current row of the sidebar as remaining percentages with bars.
2. **Refresh**: the sidebar's `refresh` button and **Refresh Claude Usage Limits** show "Checking usage limits…" in the tooltip and then the result. The values change only when Claude Code fetched again (at most about once a minute), so repeat after a minute if they did not. Clicking the button repeatedly while a query runs starts no second `claude` process (`ps`, read-only).
   **Sidebar buttons** (in a preview and in the real editor): both pages have the `refresh` icon button, the Claude page also the `layers` button, left of "+ Add" (below the heading, right-aligned, when narrow); hover shows the title, which is also the accessible name. They are hidden when the current row (or, for `layers`, every registered row) cannot be queried: signed-out or non-subscription Claude; signed-out or API key Codex; Codex run inside WSL; disabled Codex page. Judge their theme look in light, dark and high-contrast themes as part of the real-editor check.
3. **Named account**: make a named account (own `CLAUDE_CONFIG_DIR`, signed in) current through the supported flow; within seconds of the setting change the tooltip shows that account's values, matching `CLAUDE_CONFIG_DIR=<dir> claude -p "/usage"`, never the previous account's. Switch back: the other account's row keeps the values its own last query cached, and the tooltip never shows a failure recorded for another account.
4. **Re-sign-in as another account**: in a named account's terminal run `/logout` and sign in as a different Claude account. Until the new account has been queried, its row and the tooltip show no usage lines (the old cache is hidden, not shown as the new account's); after **Refresh Claude Usage Limits** they show the new account's values.
5. **Signed out**: a signed-out account (current or not) shows no usage lines and no refresh button, and the command does nothing; while it is current, `ps` (read-only) shows no `claude -p /usage` process started by the editor.
6. **Offline**: with the network disconnected, run **Refresh Claude Usage Limits**: the tooltip keeps the old rows and adds the italic line "Usage check failed". Reconnect and refresh: the line disappears and the rows update.
7. **CLI missing and expiry**: start the editor with `claude` removed from PATH: "Usage check failed" appears, with at most one attempt per 15 minutes while focused. A window disappears from the rows at its reset time (within a minute); a cache older than 24 hours is not shown.
8. **Status bar text and color**: with signed-in subscription accounts current, the text reads `Claude N% · Codex M%` (no account names), where N and M are `100 - used` rounded down of each product's shortest general window (normally 5h) as listed in the tooltip rows. A signed-out account, a Codex API key account, or one with no usage lines shows only the product name. When any general window of either product, the 7-day one included, has 30% or less left the item gets the warning background, at 10% or less the error background, and the tooltip's table shows that window; model-specific windows never tint it. After the window resets or the cache expires, the figure and color follow the remaining windows.
9. **Refresh all accounts**: with at least two signed-in subscription accounts registered (one current), run **Refresh Usage Limits of All Claude Accounts** (and, separately, the sidebar's `layers` button): a progress notification shows "Checking Claude usage limits: {label} ({done}/{total})", `ps` (read-only) never shows two `claude -p /usage` processes at once, afterwards every account's row shows newer values (collection time on hover) and "Checked the usage limits of {n} Claude accounts." appears. The external (unregistered) directory, if current, is not queried. Run it again while it is running: nothing starts. With no signed-in registered account: "No signed-in Claude account to check."
   **Cancel**: cancel the notification mid-run: the running `claude -p /usage` process ends at once (`ps`), later accounts are not queried and keep their old values, and "Cancelled after checking {ok} of {n} Claude accounts." appears.
   **Failing account**: make one account's query fail (for example an account whose sign-in Claude Code can no longer use): the others still complete, and a warning "Checked {ok} of {n} Claude accounts. Failed: <label> (<reason>)" names it with its localized reason text (the tooltip itself only says "Usage check failed").
10. **No side effects**: after the checks, the account directories have no new session transcripts under `projects/` from the usage queries (they run with `--no-session-persistence`), no other new entries beyond what a terminal `claude -p "/usage" --no-session-persistence --setting-sources user` also leaves, and `.credentials.json` was never touched by PlanSwap (it was only used by Claude Code). With a `SessionStart` hook in user settings, note whether it runs for the query.

### Codex in a local Linux desktop VS Code

Performed by the user with an installed build. Local switching saves selection and shows manual instructions; PlanSwap never exits or relaunches the desktop editor. Record editor/official-extension versions, connection context, starting/selected/effective labels and results; never record credentials or account emails. See [Codex design §5.1](codex-design.md#51-local-desktop-editor-manual-restart).

1. **Labels and instructions**: in all four languages, the switch confirmation offers **Save selection** and explains the manual steps. The pending banner explains that a restart is required and has no action button; the footer has no Codex restart control. There is no WSL shutdown instruction or delay.
2. **Cancel selection**: cancel the account-switch confirmation; selection and effective account remain unchanged.
3. **Default → named**: confirm an existing named account. Selection is saved, the pending banner appears and every editor window stays open. Confirm the pending banner is informational and the footer has no Codex restart action. The Command Palette action still shows local guidance. Save work and manually exit/relaunch the intended instance through the original launcher with the selected `CODEX_HOME`; verify the official identity and a successful new conversation.
4. **Named → default**: repeat with default, explicitly unsetting `CODEX_HOME` before launch. Verify effective selection, official identity and a new conversation.
5. **Exit cancellation and multiple windows**: keep another local/remote window open in the same instance. Saving selection and showing instructions must not close it. Cancel a later ordinary quit, then quit again within 30 seconds: PlanSwap must not reopen the editor. There is no pending helper at any interval.
6. **WSLg session**: when using `dbus-run-session`, use the original launcher again so it creates a fresh bus/keyring session. Preserve user-data/extensions arguments and workspace; record keyring access separately from account switching.
7. **Cold start**: verify each launch route separately; selection alone does not establish terminal/desktop-icon environment propagation.
8. **WSL and Claude regression**: preserve the existing supported WSL restart flow and Claude settings/reload behavior. Agents never execute real restart operations.
9. **Native Linux**: before claiming native desktop coverage, repeat the manual flow in a native desktop session or VM. The WSLg evidence alone does not establish this.

## Native Windows (user-operated)

Run on a Windows machine with the local editor, throwaway accounts and a real login for each vendor. Agents never run these steps.

1. **Claude**: add a named account, switch, open its terminal (`claude`), sign in, and confirm the panel shows the email. Confirm the Claude extension itself uses the selected directory after **Reload Window** (upstream reports say it may ignore the setting), and note where `.claude.json` is written.
2. **Shared account**: with Developer Mode off, add a shared account; a centered modal must offer to copy config files. Choose Copy files: folders are junctions, config files are copies, history stays absent. Repeat choosing Skip (and dismissing with Esc): nothing is copied and the notice mentions Developer Mode. Choose Open Developer Settings: Windows Settings opens on For developers and nothing is copied. Repeat with Developer Mode on; files must link, but a shared Codex account must have no `*.sqlite` links (its own databases appear once Codex runs with it).
3. **Codex enable/disable**: enable, check `reg query HKCU\Environment /v CODEX_HOME` is unchanged or absent for the default account; disable removes it. With a hand-set `CODEX_HOME`, enable must refuse.
4. **Codex switch**: switch to a named account, fully quit all editor windows, start the editor from the Start menu, confirm the Codex extension and its terminal use the new directory. Switch back to default; the variable must disappear.
5. **Busy checks**: with the Codex extension running (its `codex.exe` app server), converting or removing a non-current account must still work; with that account's PlanSwap terminal open, it must be refused. For Claude, with the Claude panel open on the default account, a shared account can be removed and made independent; an independent account with a live session of its own (its PlanSwap terminal running `claude`) is refused.
6. **Claude usage limits**: with a signed-in subscription account current, hover the status bar item and run **Refresh Claude Usage Limits**; the limits appear (a `claude` found on PATH, or the `claude.cmd` shim through the shell fallback) and no console window flashes. Hover again with `claude` removed from PATH: the "claude command was not found" line appears.
7. **Codex run inside WSL**: turn on `chatgpt.runCodexInWindowsSubsystemForLinux`; Codex enable and switch must be refused with the warning to use a WSL window, and the status bar tooltip must show the "Codex runs inside WSL here" note instead of usage limits. Record whether the Codex extension then really uses the WSL-side `~/.codex` and ignores the Windows `CODEX_HOME`. Turn the setting off again: the tooltip returns to normal without a reload.
